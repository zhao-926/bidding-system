# Demo 錄影腳本（約 4 分 30 秒）

> 用線上網頁版示範：<https://zhao-926.github.io/bidding-system/>
> 建議使用電腦瀏覽器、視窗寬度 ≥ 1200 px，錄影前先按右上角「**重設範例資料**」，讓畫面從第 60 分鐘的範例資料開始。
> 範例資料：5 位使用者（alice、bob、carol、dave、eve）、20 件商品、45 筆出價，其中商品 #3 有一筆撤標紀錄、#7／#10／#14／#20 無人出價（#20 最先到期，會流標）、#2 已流標、#1 已成交、#12 即將結標。
> 畫面最下方的「**本次操作**」列會在每次操作後顯示用到的資料結構與複雜度，講解時直接指著它。

| 時間 | 操作（要點什麼） | 要講的內容（資料結構與複雜度） |
|---|---|---|
| **0:00–0:25**<br>開場 | 停在「商品列表」，指一下頂列的模擬時鐘「第 60 分鐘」。 | 「這是資料結構期末專題：二手交易競標平台。系統用到 **5 種自己實作的資料結構**：Hash Table、Max-Heap、Linked List、BST、Merge Sort，**完全沒有使用內建容器**。網頁版和 C++ 的 CLI 版是同一份演算法——我把 C++ 核心一比一移植成 JavaScript，並用測試證明兩邊存出來的檔案逐位元組相同。時間用『模擬時鐘』，所以 Demo 時可以直接快轉，不用真的等。」 |

| **1:30–2:30**<br>出價（Heap + Linked List） | 1. 頂列使用者切換成 **bob**。<br>2. 點開 **#4 機械鍵盤**（目前最高價 1,900，dave）。<br>3. 出價欄輸入 **1950** → 按「出價」→ 出現紅色錯誤訊息。<br>4. 改輸入 **2000** → 出價成功。<br>5. 指出價歷史第一筆「目前最高」。 | 「先故意出太低，系統回傳**明確的中文錯誤**，告訴我最低可出價 2,000 元（最高價 1,900 ＋ 最小加價 100）。<br>出價成功後，操作列顯示：**MaxHeap.push O(log n) ＋ LinkedList.pushFront O(1)**。<br>每件商品的有效出價放在 **Max-Heap**，堆頂永遠是最高價，所以『查目前最高價』是 **O(1)**，不用每次排序。<br>出價歷史是 **Linked List**，新的插在最前面，所以由新到舊顯示，插入只要 O(1)。」 |

| **4:20–4:30**<br>結語 | 切到 `docs/benchmark.md` 的表格（或口頭帶過）。 | 「最後我用 `std::unordered_map`、`priority_queue`、`std::map`、`std::sort` 當對照組測效能：Hash Table 和隨機資料的 BST 跟 STL 同量級；Heap 慢一些，是為了多出的『任意刪除』；而**依序插入 BST 會退化成 O(n²)**——這就是為什麼最差情況很重要，改進方向是 AVL 或紅黑樹。謝謝。」 |

## 備用／補充（時間夠再講）

- **CLI 版**：終端機執行 `./build/auction_cli`，示範「`1` 註冊 → `2` 刊登 → `6` 出價 → `7` 撤標 → `11` 快轉結標」，每步下面都會印 `[資料結構] …` 提示。
- **存檔格式與驗證**：`data/sample.txt` 是 C++ 產生的存檔，JS 測試證明網頁版載入範例資料後存出的內容與它**逐位元組相同**。
- **穩定排序的價值**：先依出價數、再依價格排序時，價格相同者仍維持出價數的順序（測試 `test_two_pass_sort_relies_on_stability`）。
- **同價先到者勝**：Heap 的比較規則是「金額高者優先；金額相同時，時間早者優先」（最小加價設為 0 時可以出同價）。
